AccelEP

The primary objective is to check accelerator software before the chip exists. This page runs one small Llama on that stand-in, on the CPU.

Primary objective

A model is a list of math steps. ONNX is the file format for that list. ONNX Runtime reads the file and asks each execution provider which steps it can take. Claimed steps go to that provider. The rest stay on the CPU. That split is the graph partition.

AccelEP is the provider for an accelerator that is not on this machine. It claims matrix multiplies, a following ReLU or exact GELU, one residual, and a constant int8 weight that stays packed until the multiply. There is no chip. Behind the provider is a C++ device with its own heap. The device runs on the CPU. A match means Runtime handed over the steps you claimed, the fused steps agree with a reference, and a call log can show the order and the sizes.

This chat does not call that plugin. The host builds the prompt string. SimDevice runs the loaded SmolLM checkpoint: embedding, RMSNorm, RoPE, attention, SiLU, the residual adds, and the vocabulary projection. The reply is the text decoded from the token ids the simulator sampled. Temperature is applied after those scores exist, when the next token is chosen.

Agreement here means the software and the reference math agree. A real chip can add in a different order and round differently. That comparison is mmaprobe's job. This page does not apply a tensor-core rounding model.
